# 포우마루(Pawmaru) 작품계획서

> 반려동물 프로필 기반 맞춤형 용품 쇼핑몰

## 1. 작품배경

반려동물을 단순한 애완의 대상이 아닌 가족의 구성원으로 인식하는 문화가 확산되면서 사료, 간식, 건강보조식품, 위생용품, 장난감 등 반려동물 관련 상품의 소비가 증가하고 있다. 농림축산식품부의 「2025년 반려동물 양육현황 조사」에 따르면 국내 반려동물 양육 가구의 비율은 29.2%이며, 반려동물 한 마리당 월평균 양육비는 약 12만 1천 원으로 조사되었다.[^1]

반려동물의 종류, 품종, 연령, 체중 및 건강 상태에 따라 적합한 상품이 다르지만, 일반적인 온라인 쇼핑몰에서는 사용자가 상품 정보를 직접 비교하고 판단해야 한다. 특히 사료와 간식은 원료 및 영양 성분을 고려해야 하며, 알레르기가 있는 반려동물의 경우 부적합한 상품을 구매할 가능성도 있다.

이에 본 작품에서는 사용자가 자신의 반려동물 정보를 등록하고, 해당 정보를 바탕으로 상품의 적용 대상과 주의 성분을 확인할 수 있는 반려동물 용품 쇼핑몰을 구현하고자 한다. 또한 사용자용 쇼핑 기능과 관리자용 업무 기능을 함께 개발하여 실제 SI 프로젝트에서 요구되는 인증, 권한, 주문, 재고, 상태 관리 및 운영 배포 과정을 경험한다.

## 2. 작품주제

### 2.1 작품명

**포우마루(Pawmaru)**

### 2.2 주제

**반려동물 프로필 기반 맞춤형 반려동물 용품 쇼핑몰 구축**

### 2.3 작품 개요

포우마루는 반려견과 반려묘 보호자를 대상으로 하는 웹 쇼핑몰이다. 사용자는 반려동물의 종류, 품종, 생년월일, 체중 및 알레르기 정보를 프로필로 등록하고 상품을 검색하거나 구매할 수 있다. 상품 상세 화면에서는 등록된 반려동물과 상품 정보를 비교하여 적용 대상과 알레르기 주의 정보를 제공한다.

관리자는 별도의 관리자 화면에서 회원, 카테고리, 상품, 상품 옵션, 재고, 주문 및 리뷰를 관리한다. 주문 생성과 취소 과정에서는 재고의 차감과 복구를 트랜잭션으로 처리하여 데이터의 일관성을 유지한다.

## 3. 시장추세

### 3.1 반려가구의 증가

농림축산식품부의 국가승인통계에 따르면 2025년 국내 반려동물 양육 가구 비율은 29.2%로, 반려동물을 기르는 가구가 약 세 가구 중 한 가구 수준으로 확대되었다.[^1] KB경영연구소는 2025년 국내 반려가구를 약 591만 가구, 반려인을 약 1,546만 명으로 추산했다.[^2] 이는 반려동물 관련 상품과 서비스가 일부 소비자만을 위한 영역이 아니라 지속적인 수요를 가진 생활 산업으로 발전하고 있음을 보여준다.

### 3.2 펫 휴머니제이션과 웰니스 소비

반려동물을 가족처럼 대하는 펫 휴머니제이션(Pet Humanization)이 확산되면서 단순한 생존 목적의 사육용품보다 건강, 영양, 운동 및 정서 관리와 관련된 상품에 대한 관심이 높아지고 있다. KB경영연구소 조사에서 반려가구의 87.2%가 반려동물을 가족의 일원으로 인식했으며, 이러한 인식은 사료, 영양제, 피트니스 도구, 펫테크 제품 및 예방 의료 서비스에 대한 관심으로 이어지고 있다.[^3]

### 3.3 식품 및 건강관리 지출 증가

2025년 KB 조사에서 반려가구의 월 양육비 중 사료비 35.1%, 간식 및 건강보조식품비 22.5%로 식품 관련 지출이 전체의 57.6%를 차지했다. 이는 2023년 조사 결과인 50.8%보다 6.8%p 증가한 수치다.[^2] 따라서 반려동물의 연령, 체중, 알레르기 및 생활 특성을 고려한 상품 정보 제공의 필요성이 커지고 있다.

### 3.4 온라인 맞춤형 구매 경험의 중요성

온라인 쇼핑에서는 다양한 상품을 편리하게 비교할 수 있지만, 상품 수가 많아질수록 보호자가 자신의 반려동물에게 적합한 상품을 직접 판별해야 하는 부담도 커진다. 단순 카테고리 분류를 넘어 반려동물 프로필과 상품 속성을 연결하면 검색 범위를 줄이고 부적합한 상품 구매 가능성을 낮출 수 있다. 포우마루는 이러한 소비 흐름을 반영하여 프로필 기반 필터와 알레르기 성분 경고를 핵심 차별화 기능으로 제공한다.

## 4. 작품목표

### 4.1 최종 목표

Spring Boot와 Next.js를 기반으로 사용자와 관리자의 업무가 분리된 반려동물 용품 쇼핑몰을 구현하고, Docker와 Nginx를 이용하여 Oracle Cloud 서버에 실제 운영 가능한 형태로 배포한다.

### 4.2 세부 목표

1. 사용자와 관리자의 권한을 분리하고 서버에서 접근 권한을 검증한다.
2. 사용자가 여러 반려동물의 프로필을 등록하고 관리할 수 있도록 한다.
3. 상품명, 카테고리, 대상 동물 및 가격을 기준으로 검색과 필터 기능을 제공한다.
4. 상품 옵션별 재고를 관리하고 보유 수량을 초과한 주문을 방지한다.
5. 장바구니부터 주문, 취소 및 재고 복구까지 쇼핑몰의 핵심 업무 흐름을 구현한다.
6. 반려동물의 알레르기 정보와 상품 원료를 비교하여 주의 정보를 제공한다.
7. 관리자에게 회원, 상품, 재고, 주문 및 리뷰 관리 기능을 제공한다.
8. 주문과 재고 변경을 트랜잭션으로 처리하여 데이터 정합성을 보장한다.
9. 공통 예외 응답, API 문서 및 테스트 코드를 작성하여 신뢰성을 높인다.
10. Docker, Nginx 및 HTTPS를 적용하여 재현 가능하고 안전한 운영 환경을 구축한다.

## 5. 실용적근거

### 5.1 사용자 관점

- 여러 쇼핑몰 상품을 개별적으로 비교해야 하는 탐색 비용을 줄일 수 있다.
- 반려동물별 프로필을 저장하여 반복적으로 조건을 입력하지 않아도 된다.
- 알레르기 유발 가능 원료를 상품 구매 전에 확인할 수 있다.
- 상품 검색부터 장바구니, 주문 및 리뷰까지 하나의 서비스에서 이용할 수 있다.

### 5.2 관리자 관점

- 상품과 옵션별 재고를 통합하여 관리할 수 있다.
- 주문 상태에 따라 가능한 업무를 제한하여 잘못된 상태 변경을 방지할 수 있다.
- 판매 중지 상품과 탈퇴 회원을 논리적으로 관리하여 기존 주문 이력을 보존할 수 있다.
- 주문 및 매출 데이터를 조회하여 기본적인 운영 현황을 파악할 수 있다.

### 5.3 개발 및 포트폴리오 관점

본 작품은 단순 화면 구현이 아니라 요구사항 분석, 관계형 데이터베이스 설계, REST API, 인증·인가, 트랜잭션, 테스트, 컨테이너 및 클라우드 배포를 포함한다. 특히 주문 상태 전이와 재고 동시성은 실제 상거래 시스템에서 중요한 업무 규칙이므로 SI 및 백엔드 개발 직무의 포트폴리오로 활용할 수 있다.

## 6. 기술분석

### 6.1 Next.js와 TypeScript

Next.js는 React 기반 프레임워크로서 파일 기반 라우팅, 서버 및 클라이언트 컴포넌트, 이미지 최적화 기능을 제공한다. TypeScript를 함께 사용하여 컴포넌트 속성, API 요청 및 응답 데이터의 타입을 명확하게 정의하고 개발 단계에서 오류를 줄인다. Next.js는 Node.js 서버 또는 Docker 컨테이너 형태의 자체 호스팅을 지원하며, 공식 문서는 자체 호스팅 시 애플리케이션 앞에 Nginx와 같은 리버스 프록시를 배치할 것을 권장한다.[^4]

### 6.2 Spring Boot

Spring Boot는 독립 실행 가능한 Java 웹 애플리케이션과 REST API 구축에 적합하다. 자동 설정, 내장 웹 서버, 외부 설정, 상태 점검 등 운영 애플리케이션에 필요한 기능을 제공한다.[^5] 포우마루에서는 Controller, Service, Repository 계층을 분리하여 요청 처리, 비즈니스 로직 및 데이터 접근 책임을 명확하게 구성한다.

### 6.3 Spring Security

Spring Security를 이용하여 사용자 인증과 역할 기반 인가를 구현한다. 사용자는 `USER`, 관리자는 `ADMIN` 권한을 가지며, 관리자 API는 화면의 노출 여부와 무관하게 서버에서 접근을 차단한다. 비밀번호는 단방향 해시로 저장하고 인증 정보는 안전한 쿠키 정책을 적용하여 전달한다.

### 6.4 Spring Data JPA와 PostgreSQL

Spring Data JPA를 통해 Java 도메인 객체와 PostgreSQL 테이블을 연결한다. 회원, 반려동물, 상품, 옵션, 재고, 장바구니, 주문 및 리뷰 사이의 관계를 관계형 데이터베이스로 표현한다. 목록 조회에는 페이징을 적용하고 자주 검색되는 상품명, 카테고리 및 주문 상태에는 필요한 인덱스를 구성한다.

### 6.5 트랜잭션과 재고 정합성

주문 생성 시 주문 정보 저장과 재고 차감은 하나의 트랜잭션으로 처리한다. 처리 중 오류가 발생하면 전체 작업을 취소하여 주문만 생성되거나 재고만 감소하는 현상을 방지한다. 동시에 여러 사용자가 동일한 상품을 주문하는 상황을 테스트하고, 잠금 또는 조건부 갱신 방법을 적용하여 재고가 음수가 되지 않도록 한다.

### 6.6 Docker와 Docker Compose

프론트엔드, 백엔드 및 PostgreSQL을 독립 컨테이너로 실행한다. Docker Compose를 사용하여 컨테이너의 환경 변수, 네트워크, 볼륨 및 실행 순서를 선언적으로 관리한다. RouteOn, 포우마루 및 공용 게이트웨이는 서로 다른 Compose 프로젝트로 분리하여 한 애플리케이션의 재배포가 다른 애플리케이션의 컨테이너를 재시작하지 않도록 구성한다.

### 6.7 Nginx와 HTTPS

Nginx를 공용 리버스 프록시로 사용하여 도메인에 따라 요청을 각 애플리케이션으로 전달한다. 외부에는 80번과 443번 포트만 공개하고 백엔드와 데이터베이스 포트는 외부에 직접 노출하지 않는다. Let’s Encrypt 인증서로 HTTPS를 적용하며 HTTP 요청은 HTTPS로 영구 리다이렉트한다.

### 6.8 테스트

JUnit 5와 Spring Boot Test를 이용하여 회원 권한, 주문 상태 변경, 재고 차감, 주문 취소 및 알레르기 경고 로직을 검증한다. 프론트엔드는 Vitest로 주요 컴포넌트를 검사하고 Playwright로 회원가입부터 주문까지의 핵심 사용자 흐름을 테스트한다.

## 8. 추진일정

전체 개발 기간은 4주로 계획한다.

| 기간 | 추진 내용 | 주요 산출물 |
|---|---|---|
| 1주차 | 요구사항 분석, 화면 정의, ERD와 API 설계, 프로젝트 기본 구조 구성 | 요구사항 명세, 화면 목록, ERD, API 목록 |
| 2주차 | 인증·인가, 회원, 반려동물 프로필, 카테고리와 상품 관리 구현 | 회원·반려동물·상품 API 및 화면 |
| 3주차 | 장바구니, 주문, 재고, 취소, 리뷰와 알레르기 경고 구현 | 주문 프로세스, 재고 처리, 핵심 테스트 |
| 4주차 | 프론트·백엔드 통합, 테스트, 운영 배포와 발표 문서 작성 | 운영 서비스, API 문서, 시연 영상, 발표자료 |

- 사용자 및 관리자 요구사항 정의
- 필수 기능과 확장 기능 범위 확정
- 화면 목록과 화면 흐름 작성
- 데이터베이스 ERD 설계
- REST API 명세 초안 작성
- Spring Boot와 Next.js 프로젝트 생성
- PostgreSQL 개발 환경 연결

### 8.2 2주차: 회원 및 상품 기능

- 회원가입, 로그인 및 로그아웃
- 사용자와 관리자 권한 분리
- 반려동물 프로필 CRUD
- 카테고리와 상품 CRUD
- 상품 옵션과 재고 관리
- 상품 목록, 상세, 검색 및 필터 화면

### 8.3 3주차: 주문 업무 구현

- 장바구니 관리
- 주문 생성과 주문 내역 조회
- 옵션별 재고 차감 및 재고 초과 주문 방지
- 주문 취소와 재고 복구
- 관리자 주문 상태 변경
- 리뷰 및 별점
- 알레르기 성분 경고
- 핵심 비즈니스 로직 테스트

### 8.4 4주차: 통합 및 배포

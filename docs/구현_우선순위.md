# 포우마루 구현 우선순위

## 범위 판단 기준

4주 안에 사용자가 상품을 찾아 주문하고 관리자가 상품·주문을 관리하는 흐름을 완성한다. 외부 서비스 의존성이 큰 기능은 핵심 흐름을 완성한 뒤 진행한다.

## P0 — 반드시 완성

1. 프로젝트 기반: Docker, DB 마이그레이션, 공통 오류 응답, 배포
2. 상품: 카테고리, 목록, 검색, 상세, 옵션과 재고
3. 회원: 가입, 로그인, 로그아웃, USER/ADMIN 권한
4. 장바구니: 추가, 수량 변경, 삭제, 합계
5. 주문: 배송지 입력, 주문 생성, 재고 차감, 내역, 취소
6. 관리자: 상품·재고 관리, 주문 상태 관리
7. 품질: 핵심 서비스 테스트, 입력 검증, 모바일 화면

## P1 — P0 이후 구현

1. 배송지 관리와 반려동물 프로필
2. 구매 확인 기반 리뷰
3. 상품 이미지 업로드
4. 찜 목록과 최근 본 상품

## P2 — 일정이 남을 때만 구현

1. 실제 PG 결제 및 결제 취소
2. 배송사 조회 API
3. 개인화 추천, 쿠폰, 포인트
4. 소셜 로그인

## 4주 실행 순서

| 기간 | 결과물 | 완료 조건 |
|---|---|---|
| 1주차 | ERD, API 기반, 상품 조회 | DB 초기화 후 상품 목록·상세 API와 화면이 동작 |
| 2주차 | 인증, 관리자 상품 관리 | 회원/관리자 권한이 분리되고 상품 CRUD 가능 |
| 3주차 | 장바구니, 주문, 재고 | 주문 트랜잭션과 취소 시 재고 복구가 테스트됨 |
| 4주차 | 리뷰, UI 완성, 배포 문서 | 주요 시나리오 E2E 통과 및 HTTPS 운영 배포 |
